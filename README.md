# Мои смены — PWA

Local-first PWA для личного рабочего графика из месячного PDF Delta. В приложении нет backend, аналитики или рекламы: PDF читается PDF.js в браузере, а результаты хранятся в IndexedDB данного браузера. Внешние запросы выполняются только после явного действия пользователя для optional-интеграции Google Calendar.

## Легенда выбранного месяца — 0.4.1

В раскрываемой легенде по умолчанию видны только цвета, сочетания и отметки выбранного месяца. Снимите галочку «Только выбранный месяц» для полного списка. Выбор сохраняется при перезапуске, без сети и при восстановлении резервной копии. [Правила отображения и перенос в APK](docs/pwa-0.4.1-android-handoff.md).

## Отмена и восстановление смен — 0.4.0

В карточке дня можно отменить конкретную смену из PDF, ручной выход или koduvalve, а затем восстановить её. Отмена исключает запись из рабочего плана, часов, своей нагрузки и надбавок; Google предлагает удалить или вернуть событие при следующей синхронизации. Остальные записи дня сохраняются.

Повторный импорт сохраняет отмену неизменённой смены, завершает её при исчезновении смены и предупреждает об изменении или повторном появлении. Завершённая отмена не возобновляется автоматически. Состояние хранится отдельно от PDF и входит в резервную копию v3; старые копии v1/v2 принимаются. [Правила сопоставления, ограничения и перенос в APK](docs/pwa-0.4.0-android-handoff.md).

## Полная легенда календаря — 0.3.6

Легенда объясняет все ручные типы записей, цвета смен разной длительности, смешанный фон koduvalve со сменой и палитру своих заметок. Образцы используют цвета самих дней. Полная легенда помещается по высоте без обрезания и доступна offline. [Описание и перенос в APK](docs/pwa-0.3.6-android-handoff.md).

## Ручные записи в календаре — 0.3.5

Ручные смены и koduvalve окрашивают день календаря так же, как записи PDF; время отображается по введённой записи. Личные заметки и отсутствия тоже получают цвет дня. Ручные рабочие записи входят в обычную сверку Google Calendar, включая изменение и удаление без PDF. Учёт отсутствий остаётся отдельной настройкой; перед отправкой показываются изменения. [Технические подробности и перенос в APK](docs/pwa-0.3.5-android-handoff.md). Правила выпуска закреплены в [AGENTS.md](AGENTS.md).

## История обновлений — 0.3.4

В настройках появился раздел «История обновлений»: версии, даты и короткие описания изменений от первых выпусков до текущего. Текущая версия раскрывается сразу; остальные — по нажатию. История работает без интернета. [Описание и перенос в APK](docs/pwa-0.3.4-android-handoff.md).

При каждом выпуске добавлять запись в начало `src/update-history.ts` вместе с повышением версии пакета. Пользовательские тексты держать короткими; технические правила и результаты публикации записывать в отдельный handoff в `docs`.

## Отпуск P-et и ручное koduvalve — 0.3.3

`P-et` распознаётся как дополнительный оплачиваемый отпуск (eriteenistuja lisapuhkus), в том числе в уже сохранённых графиках без повторного импорта. Через общую форму можно добавить koduvalve с произвольными датами и временем: надбавка входит в прогноз зарплаты, домашние часы учитываются отдельно от работы. Нажатие на запись с карандашом открывает редактирование и удаление. «После смены» переносит интервал к окончанию смены, сохраняя введённую длительность.

[Лог изменений, правила расчёта, миграция и проверки для переноса в APK](docs/pwa-0.3.3-android-handoff.md).

Свайп по ячейкам больше не запускает отложенное долгое нажатие. Свёрнутый блок «Нагрузка сотрудников» выделен цветом, рамкой и иконкой. [Описание исправления и перенос в Android](docs/pwa-0.3.1-android-handoff.md).

## Личные события и прогноз выплат — 0.3.0

Календарь работает и без PDF. «Добавить» или долгое нажатие на день открывает свои записи, Erakorraline, дополнительные выходы, болезнь/уход за ребёнком и ежегодный отпуск. Ручные данные сохраняются отдельно от PDF; совпавший выход связывается явно. Прогноз различает оклад/надбавки, отпускные, пособие работодателя и Tervisekassa; периоды и начисления уточняются в настройках. Полные PDF дают оценку, а не доказательство фактического дохода.

## Запуск и проверка

```bash
npm ci
npm run dev
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

`dist/` — готовая статическая публикация. Для GitHub Pages в репозитории `duty` используется `VITE_BASE=/duty/ npm run build`.

Требуется Node.js 22.13+ (рекомендуется актуальная версия 22 LTS). Браузерные тесты запускают production-сборку с настоящей CSP и синтетическим PDF без персональных данных. `npm run icons` пересоздаёт установочные PNG из существующего SVG через Chromium.

## Архитектура

- `src/employee-workload.ts` — рейтинг всех D-номеров выбранного PDF по часам месяца или общей сумме за доступные месяцы. На экране «Анализ» блок «Нагрузка сотрудников» по умолчанию свёрнут; сортировка переключается заголовками «Месяц» / «Всего» и сохраняется на устройстве. [Базовая спецификация для Android APK](docs/employee-workload-android-handoff.md) фиксирует правила расчёта и примеры; [изменения интерфейса 0.3.2](docs/pwa-0.3.2-android-handoff.md) описывают текущую таблицу.
- `src/parser.ts` — координатный парсер первой страницы: находит строку заголовков дней и все строки `D…`, включая нижние слои ячейки. Поэтому `12 + V4`, `8P + V8` и разбитое на две строки `V8,25` сохраняются как отдельные отметки одного дня. Неизвестные коды (`#…`, `Õ`, `TK4`) сохраняются дословно, а не превращаются в часы по догадке.
- `src/schedule.ts` — доменные правила. В частности, точная пара `16` последнего дня + обычный `8` первого дня следующего месяца отображается как одна суточная смена `24`; `8P` и `V8` самостоятельны.
- `src/roster.ts` — выбор текущего D-номера, нормализация его смен через месяцы и read-only представление смен других D-номеров. Все D-строки PDF остаются локально доступными после импорта.
- Если ровно один D-номер полного графика имеет обычный `16` в последний день месяца, это подтверждённая 24-часовая смена до 08:00 следующего дня даже без следующего PDF. Исходные `16` остаются в PDF/marks; вывод, аналитика и Google используют `24`. При двух таких D-номерах требуется явная пара `16 + 8`; `8P` и `V8` не поглощаются. Неполный старый набор строк не доказывает уникальность.
- `src/intervals.ts` — рабочие интервалы, время Таллина, текущая/следующая смена. Расчёт независим от Google и включает неподтверждённые пограничные 16 часов, которые экспорт пока пропускает.
- `src/month-analysis.ts`, `src/analysis-rules.ts`, `src/analysis-view.ts` — расчёт, правила с редакцией/источниками и представление. Часы по исходному PDF, полные смены по дате начала и часы внутри календарного месяца различаются; последний показатель обрезает интервалы по полуночи. Часы плановые по местному времени, не табель фактической работы на переходах летнего времени.
- `src/calendar-sync.ts` — чистая модель Google-событий, idempotent diff, ownership markers, обнаружение ручных изменений/удалений и безопасный apply-план.
- `src/google-calendar.ts` — lazy-loaded Google Identity Services и минимальный Calendar REST gateway. Access token существует только в памяти вкладки.
- `src/db.ts` — IndexedDB v5: `months`, `pdfs`, `settings`, `syncs`, `revisions`, `events`, `payroll`. Запись считается успешной после commit транзакции; импорт атомарно сохраняет PDF, месяц, выбранный номер и предыдущую версию. Обновление схемы не очищает данные.
- `src/backup.ts` — локальный JSON-экспорт с PDF и проверяемое восстановление в одной транзакции. Копия содержит все сохранённые D-строки и локальные сведения Google, включая email/идентификаторы событий, но не OAuth-токен. Храните файл как личный документ. Перед заменой данных скачивается текущая копия. Лимит восстановления — 100 МБ.
- `src/documents-view.ts`, `src/import-review.ts`, `src/ui.ts` — документы, сравнение импорта, общие диалоги/фокус/иконки. Открытый диалог сохраняется при изменении сети.
- `src/main.ts` — mobile-first UI и import/sync flows. Повторный импорт заменяет месяц, SHA-256 фиксирует версию файла; месяц никогда не дублируется.

Оригинальный PDF сохраняется только в локальном IndexedDB приложения вместе с именем, хэшем, временем импорта, выбранным Delta-номером, сменами и статусом calendar sync. Это позволяет открыть исходный файл offline на вкладке «Графики». Удаление месяца удаляет лишь эту внутреннюю копию и данные PWA; исходный файл пользователя в «Загрузках» или Files не затрагивается.

## Offline, PWA и privacy

Vite PWA генерирует manifest и Service Worker с precache приложения и локальной копией PDF.js worker. PDF.js загружается в приложение при импорте, но остаётся в precache для первого офлайн-импорта. При обновлении SW запрашивает подтверждение; перезапуск отложен до завершения действия/закрытия диалога. IndexedDB не находится в cache и не удаляется. После загрузки precache приложение запускается и импортирует PDF без сети. Production CSP разрешает собственные ресурсы и необходимые Google endpoints. Только в dev разрешены inline-стили для Vite HMR. Для GitHub Pages нужен HTTPS (предоставляется Pages).

После импорта приложение запрашивает устойчивое хранение. Статус и оценка занятого места доступны в настройках; это не защита от ручного удаления браузерных данных. В разделе «Графики» доступны резервная копия и возврат предыдущей версии месяца. PDF-импорт ограничен 20 МБ, читается первая страница с текстовой таблицей. Сканы и защищённые паролем документы требуют исходного незашифрованного PDF.

На iOS Safari установите через Share → Add to Home Screen. Проверка Safari/iOS из Linux не выполнялась; ручной чек-лист: standalone запуск без сети, safe-area на iPhone с notch, импорт из Files, dark/light theme, удаление данных и обновление PWA.

## Google Calendar

Интеграция использует Google Identity Services token model без backend и без client secret. Запрашиваются scopes `https://www.googleapis.com/auth/calendar.events.owned` и минимальный `https://www.googleapis.com/auth/userinfo.email`; события создаются в `primary`. После OAuth основной email читается через Google OAuth2 UserInfo и сохраняется только локально. Обычное получение нового токена всегда использует `prompt: ''` и сохранённый email как `login_hint`, а `prompt: 'select_account'` без hint — только отдельное действие «Сменить Google-аккаунт». PDF, остальные строки графика и access token в Google не передаются и долговременно не сохраняются.

Каждое событие получает `extendedProperties.private` с marker, анонимным локальным Google-profile ID, месяцем, D-номером и стабильным sync key. Profile ID не является email или Google user ID: email используется локально только для выбора соответствующего profile ID и как следующий GIS `login_hint`. Перед patch/delete PWA заново читает событие и проверяет все marker-поля; событие без точного marker никогда не меняется. Локальный `syncs` store сохраняет event ID, последний подтверждённый draft и etag отдельно для каждого выбранного email. Поэтому повторный импорт показывает add/change/remove diff, повторная синхронизация не создаёт дублей, а ручные правки или удаления в Google обнаруживаются до восстановления по PDF.

Для опубликованной Pages-версии в OAuth Web Client нужно добавить Authorized JavaScript Origin ровно `https://konduktor13.github.io` — без `/duty/`, завершающего `/`, query или fragment. Redirect URI для GIS token popup flow не требуется.

Сверка читает максимум четыре события одновременно. После каждой успешной записи/удаления сохраняется контрольная точка: при сбое повторная проверка продолжает с фактически выполненных действий. Для HTTP 429/5xx предусмотрены два ограниченных повтора; запросы Calendar имеют таймаут. При загрузке GIS после сетевой ошибки можно повторить вход без перезагрузки вкладки.

## GitHub Pages вручную

1. Создайте репозиторий и отправьте этот каталог в него.
2. Workflow `.github/workflows/deploy-pages.yml` уже существует: он выполняет установку, unit- и браузерные тесты, сборку с путём репозитория и публикацию `dist`.
3. В Settings → Pages выберите GitHub Actions.
4. После публикации внесите origin хоста Pages (без пути репозитория) в OAuth Authorized JavaScript origins.

## Тесты и ограничения

`npm test` проверяет PDF parsing, многослойные V-коды, повёрнутую таблицу, границы месяцев, переключение D-номера, чужие смены, IndexedDB migration boundaries, Google sync add/change/remove/idempotency/ownership, OAuth prompt и изоляцию нескольких Google-аккаунтов. Реальные персональные PDF читаются только локальными regression-тестами вне публичного репозитория. Safari требует проверки на физическом Apple-устройстве.
