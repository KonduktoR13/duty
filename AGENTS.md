# Правила работы с PWA «Мои смены»

## Каждый выпуск

При публикации новой версии обязательно:

1. Повысить версию в `package.json` и `package-lock.json` (например, `npm version X.Y.Z --no-git-tag-version`).
2. Добавить в начало `src/update-history.ts` запись этой же версии с фактической датой выпуска, коротким заголовком и понятными пользователю изменениями. Это история в настройках приложения; одной записи в README или техническом документе недостаточно. Проверить, что текущая версия раскрыта и история доступна offline.
3. Обновить README и создать `docs/pwa-X.Y.Z-android-handoff.md`: проблема, итоговое поведение, правила/ограничения, данные и миграции, перенос в APK, выполненные проверки. История приложения содержит пользовательские изменения, handoff — технические подробности.
4. Запустить `npm test`, `npm run test:e2e`, сборку с `VITE_BASE=/duty/ npm run build` и `git diff --check`. Браузерные проверки используют production-сборку. Не добавлять персональные PDF, снимки и посторонние файлы в коммит.
5. Если публикация поручена пользователем: commit/push в `main` запускает `.github/workflows/deploy-pages.yml` и публикацию GitHub Pages. Сохранять существующие URL, scope service worker, IndexedDB и локальные данные.
6. Дождаться успешного workflow и проверить публичную PWA https://konduktor13.github.io/duty/ и её `version.json`. В handoff записать release commit, ссылку и результат workflow, фактические публичные проверки; при необходимости оформить отдельным документационным коммитом `[skip ci]`.

Не заявлять, что выпуск опубликован или проверка прошла, до получения результата. Реальный Google-аккаунт пользователя не нужен для локальных регрессионных проверок: проверять план add/change/remove, стабильные ключи, отсутствие дублей, ownership и напоминания существующими тестами.
