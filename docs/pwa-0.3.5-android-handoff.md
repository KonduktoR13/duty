# PWA 0.3.5 — ручные записи в календаре

Дата выпуска: 18.11.2026. Пользователь поручил исправление, повышение версии и публикацию.

## Исправления

Раньше сетка календаря и подробности дня строились только по PDF. Ручные записи добавлялись поверх маленькими символами, поэтому день с koduvalve оставался пустым. Теперь `personalCalendarMarks()` строит отображение по `personalPlan().work`: ручные смены, домашние дежурства, связанные с PDF выходы и отсутствие используют тот же разрешённый план, что анализ, карточка следующей смены и прогноз выплат.

- Ручной koduvalve получает обычный цвет `home-duty`; совместные отметки работы и домашнего дежурства — существующий смешанный фон. Дополнительные и экстренные выходы получают рабочий цвет. Отпуск — цвет отпуска, прочие личные дни — цвет записи. Рабочий фон сохраняется при добавлении заметки на день смены.
- Ручное время показывается точно, без повторного вывода времени из кода PDF. В списке каждая ручная запись показывается один раз, с редактированием и удалением. Подробности дня сохраняют кнопку редактора. Сетка при переходах между месяцами использует тот же источник.
- Часы и надбавка koduvalve уже учитывались в личном прогнозе; формулы выплат не менялись. Домашние часы остаются отдельно от рабочих. Пересечения и явное связывание с PDF обрабатывает существующий `personalPlan`; спорный выход не добавляется второй раз.

## Google Calendar

`desiredPersonalDrafts()` включает ручные рабочие выходы и koduvalve в обычную сверку, даже если PDF отсутствует и настройка учёта отсутствий выключена. Настройка `syncPersonal` теперь относится только к учёту отсутствий; подпись и пояснение обновлены. Личные заметки, суммы и причины отсутствий не экспортируются.

Без PDF раньше сохранялись все прежние draft, а существующие ручные ключи не заменялись. Теперь ручные ключи пересобираются: редактирование даёт change, удаление — remove, повторная сверка не добавляет дублей. События прежнего PDF сохраняются, когда источник недоступен. Связанные выходы сохраняют ключ PDF.

Создание и изменение событий по-прежнему требуют обычного действия синхронизации с предварительным просмотром. Автоматической отправки при сохранении записи нет. Сохраняются ownership, Google-профили и напоминания общего механизма синхронизации.

## Данные и перенос в APK

Версия **0.3.4 → 0.3.5**, IndexedDB **v5**, backup **v2**. Новых хранилищ и миграций нет; сохранённые ручные записи отображаются после обновления без пересоздания. Для APK перенести построение отображения из разрешённого личного плана и правила сверки Google, включая изменения/удаления без PDF. Учесть уточнённый смысл `syncPersonal`.

В корневом `AGENTS.md` закреплены правила каждого выпуска, включая обязательную запись в истории обновлений внутри приложения.

## Проверки

Локально прошли **125 unit/regression-тестов**; один тест с внешним персональным PDF пропущен, поскольку файл не передан. Прошли все **18 браузерных сценариев** исходного набора и повторно **6 сценариев личного календаря**, включая новый сценарий без PDF (итоговый набор — 19). Проверены цвет koduvalve, точное время, смешанный фон, редактирование, удаление, сохранение после reload и навигации, отсутствие дублей в списке, обе темы и ширина 320 px, история текущей версии и offline. Сборка с `/duty/` и `git diff --check` прошли. Реальный Google-аккаунт и физические устройства не использовались: план синхронизации проверен тестами.
