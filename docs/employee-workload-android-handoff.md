# Нагрузка сотрудников: перенос в Android APK

Реализовано в PWA «Мои смены», версия **0.2.0**, сортировка по двум колонкам добавлена в **0.2.1**. Этот документ предназначен для новой сессии Codex, которая будет переносить функцию в отдельный Android-проект. В этой задаче изменялась только PWA; Android APK не изменялся.

## Интерфейс

На экране «Анализ» добавить блок **«Нагрузка сотрудников»** после личных показателей часов/смен и перед прогнозом зарплаты. Использовать месяц, выбранный общей навигацией экрана.

- При открытии экрана и смене месяца блок свёрнут.
- Заголовок содержит количество D-номеров, позицию выбранного сотрудника и способ сортировки: `D-номеров: 28 · D12: 5 из 28 · За месяц` либо `· Всего`.
- При раскрытии видна таблица `Место | D-номер | Месяц, ч | Всего, ч`.
- **В 0.2.1 заголовки «Месяц, ч» и «Всего, ч» стали кнопками сортировки**. Нажатие выбирает соответствующую колонку, всегда по убыванию; повторное нажатие активной колонки порядок не меняет. Дополнительных кнопок над таблицей нет.
- Активный заголовок выделен цветом и стрелкой ↓; значения его колонки выделены жирным. Вся ячейка доступна для нажатия (высота минимум 44 px), кнопки доступны с клавиатуры; в PWA у заголовка используется `aria-sort="descending"`.
- Исходный режим — по месячным часам. Последний выбор сохраняется локально под ключом `employeeWorkloadSort` (`month` или `total`) и переносится в резервной копии. Сохраняется при смене месяца, сотрудника, страницы и перезапуске приложения. Неизвестное/отсутствующее значение означает `month`.
- Строка выбранного D-номера выделена цветом и помечена «Вы». Строки таблицы не переключают выбранного сотрудника.
- Показывать всех сотрудников **из PDF выбранного месяца**, включая сотрудников с нулём рабочих часов. D-номер, встречающийся только в других месяцах, в список не добавлять.
- Если выбранного сотрудника нет в PDF, личный анализ показывает «Нет данных», но список других сотрудников остаётся доступным. Личная позиция и выделение отсутствуют.
- Для месяца без загруженного PDF таблицы нет.
- Таблица помещается на экране шириной 320 px без горизонтальной прокрутки. Поддерживаются светлая/тёмная темы и доступное раскрытие с клавиатуры/средствами доступности.
- При фоновой перерисовке того же месяца и смене выбранного D-номера раскрытый блок остаётся раскрытым. После ухода со страницы или смены месяца он снова свёрнут. Это временное состояние интерфейса, не настройка хранилища.

## Расчёт

**Часы плановые, в местном времени Europe/Tallinn**, как существующий показатель PWA «В пределах месяца». Это не фактический табель.

1. Собрать отметки сотрудника из всех доступных PDF и выполнить существующую нормализацию переходящих смен.
2. В рабочие интервалы включать только `kind: hours`. Рабочая смена начинается в 08:00; конец определяется её продолжительностью в местных часах.
3. Исключить домашнее дежурство V, возможные выходы #, отпуск и неизвестные коды. Сохранить правила самостоятельных отметок, например `8P`.
4. Обычные `16` последнего дня + обычные `8` первого дня следующего месяца нормализуются в одну смену `24`. Отметка `8` поглощается, двойного учёта нет.
5. Единственный D-номер с обычными `16` в последний день **полного** PDF также подтверждает смену `24` без следующего PDF. Если владельцев несколько или график неполный, продолжение без пары `16 + 8` не угадывается. Эти правила уже существуют в PWA; рейтинг их не переопределяет.
6. Обрезать интервалы границами календарного месяца: от первого числа 00:00 включительно до первого числа следующего месяца 00:00 исключительно. Входящая часть смены предыдущего месяца учитывается, если она известна.
7. Сумму каждого месяца округлять до 0,1 ч по правилу существующего анализа. Десятичный разделитель — запятая; лишний `,0` не показывать.
8. `Всего` — сумма этих месячных значений **только за загруженные месяцы, в PDF которых есть этот сотрудник**. Часы, переходящие в незагруженный месяц или месяц без строки сотрудника, в общий итог не добавлять. Итог также привести к 0,1 ч.
9. При неполном периоде под итогом показывать `K из N мес.`: K — число загруженных месяцев с данным D-номером, N — общее число загруженных месяцев. Месяц с существующей строкой и нулём часов считается доступным; отсутствующая строка не подменяется нулём.
10. Сортировать по выбранной колонке: часы **выбранного месяца** либо **общая сумма за доступные месяцы**, по убыванию. При равенстве использовать естественный числовой порядок D-номеров (`D2` перед `D10`). Другая колонка на порядок не влияет.
11. Равные значения выбранной колонки получают одинаковое место с пропуском следующих мест: `1, 1, 3, 4`. При переключении сортировки пересчитывать места всех строк и личную позицию в заголовке.

Под таблицей пояснить способ расчёта и число загруженных месяцев. Указать, что без соседних графиков данные на границах могут быть неполными. Если старое хранилище содержит только выбранный D-номер или `rosterComplete: false`, показать сообщение о неполном списке и необходимости повторного импорта PDF. Все расчёты локальные.

## Примеры для проверки переноса

| Исходные данные | Ожидаемые часы |
| --- | --- |
| D12: `16` 31 августа и `8` 1 сентября, оба PDF загружены | Август 16; сентябрь 8; всего 24 |
| D12: `24` 31 августа; сентябрь не загружен | Август 16; всего 16 |
| D12: `24` 31 августа; сентябрь загружен, D12 отсутствует | Август 16; всего 16; доступен 1 из 2 месяцев |
| D12 и D40: по `16` 31 августа; сентябрьские строки пустые | Август по 16; сентябрь по 0; неподтверждённые 8 часов не добавляются |
| D2 и D10: по 24 ч; D40: 8 ч; D12: 0 ч | Порядок D2, D10, D40, D12; места 1, 1, 3, 4 |
| `8,25`, `V4`, `#12`, `P`, неизвестный код | Только 8,3 рабочих часа |
| Смена `24` через переход летнего времени | 24 плановых местных часа |

## Реализация PWA

- `src/employee-workload.ts`: чистая функция `rankEmployeeWorkload(months, monthId, sort = 'month')`, результат `{ deltaNumber, rank, monthHours, totalHours, availableMonths }`.
- `src/month-analysis.ts`: `calendarWorkHours` строит интервалы сотрудника один раз для всех запрошенных месяцев; `hoursWithinMonth` общий для рейтинга и личного `calendarHours`.
- `src/roster.ts`, `src/schedule.ts`, `src/intervals.ts`: строки PDF, старые записи, нормализация и интервалы.
- `src/analysis-view.ts`: таблица, заголовок, пояснения, отображение при отсутствии выбранного сотрудника.
- `src/experience.css`: стили блока на основе существующих переменных темы.
- `src/main.ts`: сохранение раскрытия при перерисовке того же месяца.
- `tests/employee-workload.test.ts`: границы, пропуски месяцев, одинаковые места, дробные часы, старые данные и отсутствующий выбранный сотрудник.
- `e2e/app.spec.ts`: импорт двух PDF, свёрнутое состояние, клавиатура, смена месяца/D-номера, мобильный экран, обе темы и фоновая перерисовка.

Функция использует уже сохранённые строки PDF: миграция IndexedDB не нужна. В 0.2.1 в допустимые настройки резервной копии добавлен `employeeWorkloadSort`; формат копии остаётся версии 1, старые копии совместимы. Android-версия должна сохранять все D-строки, чтобы показать полный список.

## Выпуск PWA 0.2.0

- Версия поднята в `package.json` и корневых записях `package-lock.json`.
- `vite.config.ts` читает версию из `package.json`, выводит `dist/version.json` и добавляет его в precache service worker с revision, равной версии. Поэтому повышение версии изменяет сгенерированный `sw.js`, даже если остальные ресурсы совпадают.
- Версия сборки видна в настройках.
- Service worker проверяется при возвращении приложения на экран, восстановлении сети и раз в час. Проверки при возврате/сети ограничены интервалом в минуту; офлайн и скрытая вкладка пропускаются.
- Сохранено предложение «Доступна новая версия» с кнопкой «Перезапустить». Незавершённое действие/открытый диалог блокирует перезапуск; локальные графики сохраняются.
- Чтобы установленная PWA получила обновление, нужно **опубликовать новую сборку по прежнему адресу** вместе с `sw.js` и `version.json`. Рабочий каталог сам по себе не обновляет размещённую PWA. При следующем запуске старая версия обнаружит изменённый worker штатным механизмом; дополнительные фоновые проверки доступны после применения этой версии.
- Не менять имя файла worker, область регистрации, адрес приложения или версию IndexedDB ради этого выпуска.

Проверки выпуска: `npm test` и `npm run test:e2e` (включает production-сборку). Тест обновления проверяет уведомление при возвращении сети и сохранность графика после перезапуска. В 0.2.1 добавлены проверки ранжирования по общим часам, сохранения настройки в копии и переключения заголовками с сохранением фокуса/выбора после перезапуска. Safari/iOS на физическом устройстве в этой задаче не проверялись.

## Выпуск PWA 0.2.1

Версия поднята до 0.2.1 в package-файлах; общий механизм сборки автоматически обновляет версию в настройках, `version.json` и revision service worker. Опубликовать по прежнему адресу. Список по-прежнему содержит сотрудников только из PDF выбранного месяца, даже при сортировке по общей сумме; правила расчёта часов не изменены.
