# PWA 0.3.0 — личный календарь и выплаты; описание для переноса в Android

Дата: 30.10.2026. Область работы — **только PWA**. Android в этой задаче не изменялся.

Это описание фактически выполненных изменений и принятых решений; оно имеет приоритет над историческим [проектом изменений](manual-events-and-payroll-plan.md). Пользователь 30.10.2026 явно разрешил реализацию и публикацию. Данные приложения остаются локальными, backend не добавлен.

## 1. Что получает пользователь

Сохраняются три вкладки: **Календарь / Анализ / Графики**. Новые функции открываются из одной кнопки, без отдельных постоянных разделов для каждого вида записи.

| Запись | Где видна | Часы и выплаты |
| --- | --- | --- |
| Своя запись | Цветной маркер, карточка дня, список | Необязательные часы в отдельном счётчике; зарплату и рейтинг не меняет |
| Erakorraline | Рабочий выход с датой/временем | Отдельная оплата ×1,5; если базовая часть уже оплачена, только остаток ×0,5; либо компенсация отдыхом |
| Дополнительный выход | Рабочий выход с датой/временем | Баланс всего учётного периода; не автоматическая доплата за каждый час вне PDF |
| Больничный | Период собственной болезни | Пропущенная работа, уменьшение оклада, отдельные пособия работодателя/Tervisekassa |
| Уход за ребёнком | Подвид больничного с основанием листа | Tervisekassa с первого дня; ставки/пределы по основанию |
| Отпуск | Интервал ежегодного оплачиваемого отпуска | Дни без государственных праздников, уменьшение оклада, отпускные по применимой базе |
| Компенсационный отдых | Через баланс/запись компенсации отдыхом | Оплачиваемое освобождение от работы; не ежегодный отпуск и не неоплаченное отсутствие |

## 2. Маршруты и UI

### Календарь

- «Сегодня» и **«＋ Добавить»** — одна строка ниже hero. Переключатель **«Календарь / Список»** — следующая строка, чтобы всё помещалось на 320 px.
- В открытом дне — **«＋ Добавить на этот день»**. Нижняя панель располагается выше навигации и прокручивается при длинном содержимом.
- Удержание дня около 480 мс открывает тот же редактор. Смещение более 10 px, отмена pointer и завершение жеста сбрасывают таймер; последующий click подавляется. Горизонтальные свайпы месяцев сохранены.
- При входе из дня дата берётся из дня; общая кнопка использует выбранный день, сегодня в текущем месяце либо первое число открытого другого месяца.
- До первого PDF есть вторичное действие **«Добавить запись без PDF»**. После создания записи доступна обычная сетка даже без источника.
- Пользовательские цвета показываются небольшими маркерами. Цвет смены/код PDF не перезаписывается. Больничный/отпуск обозначаются отдельным маркером и полосой.
- В списке длинный период показан одной строкой диапазона, не десятками одинаковых карточек.
- Активная болезнь/уход заменяет hero компактной карточкой с действием **«Завершить / изменить»**. Выходы из актуального личного плана участвуют в следующей смене.

### Общий редактор

Сначала пять видимых вариантов; после выбора типа остаётся компактное название с «Изменить». Для болезни второй выбор **«Болею сам / Ухаживаю за ребёнком»**. Erakorraline написано на эстонском, как просил пользователь.

Шапка и сохранение закреплены, середина прокручивается. После сохранения открывается месяц и день записи. Закрытие изменённой формы требует подтверждения отказа от ввода. Ошибка хранения остаётся в редакторе, форма не исчезает. Удаление имеет 12-секундную возможность отмены. Смена сети/появление обновления не пересоздаёт редактор.

Подсказки **«?»** — кнопки с зоной не меньше 44 px, доступны по tap, Enter/Space. Открывают отдельный диалог поверх формы; значения не теряются, закрытие возвращает фокус. Источники внутри подсказок открываются отдельно. Hover не требуется.

### Своя запись

Название, дата, «Весь день / Время / Только часы», шесть цветов, необязательный текст. Поддерживается десятичная запятая. В режиме «Только часы» время начала не придумывается. Записи с интервалом распределяют часы по границам месяцев; простое число часов относится к выбранной дате.

### Рабочий выход

Начало/окончание с датой, быстрые **4 / 8 / 12 / 24 ч**, план/отработан, комментарий. Кнопка «Начать после смены этого дня» подставляет фактическое окончание интервала PDF. Конец следующего дня показывается датой. Интервалы длиннее 48 ч нужно разделить.

Для Erakorraline — деньги/отдых. В подробностях можно указать, что базовая часть ×1 уже оплачена: тогда остаётся ×0,5. **Связывание с PDF не подтверждает оплату базовой части.** Для обычного дополнительного выхода способ компенсации задаётся на весь учётный период.

Если совпадает интервал PDF, появляется явный выбор «Это та же смена». Без подтверждения пересечение не добавляется второй раз; в анализе виден конфликт. Частичное пересечение требует изменить время. Подтверждённая связь сохраняет категорию оплаты и исходный PDF.

### Болезнь и уход

Поля начала и последнего дня включительно; «Ещё продолжается» разрешает открытый лист. Закрывается тот же случай, не новый. Формулировка «последний день листа» отделяет его от первого дня выхода на работу.

В подробностях: основание листа, дата исходного случая, связь с продолжением, режим отсутствия относительно утверждённого графика, автоматическая/введённая ставка, выплата и фактически полученная сумма. Имена детей, диагнозы и персональные коды не требуются.

Исходный случай определяет отсчёт дней и год дохода; новый месяц или смена ухаживающего не начинают лимит заново. В доход пользователя входят только его собственные интервалы. При сложном чередовании/особом основании можно ввести подтверждённую ставку или общую сумму Tervisekassa за свой интервал.

Сохранение локальной записи **не открывает официальный лист** и не подаёт заявление работодателю. Есть краткое пояснение, без отдельного обязательного ознакомления.

### Отпуск

Начало/конец, план/подтверждён. Подробности содержат источник ставки и ожидаемую дату/способ выплаты. Праздники не расходуют ежегодный отпуск. Нельзя незаметно считать LHPu или компенсационный отдых ежегодным оплачиваемым отпуском.

Один отпуск через границу месяца хранится одной записью и имеет одну применимую базу среднего. Дни и начисление разбиваются на месяцы. При совпадении с P из PDF деньги не суммируются второй раз.

Если болезнь пересекается с отпуском, редактор предлагает явно подтвердить **«Прервать отпуск»**. Исключённые даты сохраняются у отпуска; оба события записываются одной транзакцией. Автоматического переноса оставшихся дней на произвольные даты нет.

## 3. Мой D-номер и просмотр коллег

В «Периоды и начисления» есть личный D-номер. Существующий переключатель в шапке меняет показываемый график. При миграции текущий D становится первоначальным личным номером.

Просмотр коллеги не переносит на него личную болезнь/зарплату. Кнопка добавления явно возвращает в свой календарь. Финансовые личные карточки не показываются под чужим номером. Рейтинг сотрудников по-прежнему считается только по PDF — сведений о личных изменениях коллег нет.

При смене собственного номера исторические рабочие события сохраняют прежний owner. Автоматическая реконструкция карьеры по разным D не производится: при необходимости исторический номер можно выбрать/уточнить. Собственные заметки сохраняются независимо от рабочего номера.

## 4. Расчётная модель

Чистая реализация: [personal.ts](../src/personal.ts). Полный контракт и валидация: [personal-types.ts](../src/personal-types.ts).

### Интервалы и качество

- PDF остаётся неизменным. Поверх исходных интервалов применяются ручные выходы, связи и отсутствие.
- Интервалы считаются до минуты в местном времени **Europe/Tallinn**. Денежные вычисления не проходят через округление аналитики до десятых часа.
- Сохраняются разные показатели: полные смены по дате начала, исходные часы PDF, часы внутри месяца, личные часы.
- Полный набор графиков даёт **оценку**, а не подтверждённую зарплату. Фактические месячные/годовые значения заменяют оценку, не прибавляются к ней.
- Если даже базы для оценки нет, часть выплаты помечается неизвестной; сумма известных частей не называется полным ожидаемым доходом.

### Оклад и отсутствие

Palgajuhend 3.7–3.8: обычный месячный оклад не умножается на фактически нарисованные часы; при отсутствии используется выбранное основание.

- После утверждения графика: пропущенные рабочие часы × часовая ставка полного оклада месяца.
- Уже в утверждённом графике: календарная норма — месячная норма / календарные дни.
- При известном свободном дне исходного графика в режиме пропущенных часов вычета нет.
- **Отсутствующий PDF не равен свободным дням.** Без источника применяется явно оценочная календарная пропорция.
- Пропущенные ночные/V/праздники не начисляются как выполненные. Asendamine в прогнозе пропорциональна оставшемуся basePay; индивидуальное основание может быть уточнено фактическим начислением.

История оклада/процента имеет даты действия; смена внутри месяца рассчитывается по частям дат. Текущая смена оклада не стирает старые параметры. Базовые прежние контрольные начисления сохраняются.

### Erakorraline и обычные сверхурочные

По palgajuhend 4.4: отдельное erakorraline — расчёт по окончании месяца; обычные сверхурочные — по окончании учётного периода. Пятидневный критерий не используется как автоматический классификатор.

Erakorraline: часовая ставка месяца × часы ×1,5. Если отдельно уже оплачено ×1, применяется остаток ×0,5. Ночные 25% и праздничная надбавка добавляются отдельно, без повторной базовой части и без перемножения коэффициентов. Ночные, V и праздники сохраняют прежний проверенный порядок округления часовой надбавки.

Учётный период настраивается: начало с первого числа, длительность, деньги/отдых, подтверждение завершённого табеля. Часы erakorraline исключаются из повторного обычного overtime. Для оценки используется уменьшенная норма; оплачиваемый компенсационный отдых даёт кредит времени. Деньги за обычные сверхурочные появляются в последнем месяце только при полном наборе графиков, завершённом периоде и явном подтверждении пользователем именно этого табельного периода. Подтверждение прошлого периода не переносится автоматически на следующий.

Ставка обычной компенсации — сумма basePay периода / уменьшенная норма × часы превышения ×1,5. Неизвестный/неподтверждённый период показывает баланс без обещания выплаты.

### Периоды среднего и данные истории

- Пособие работодателя: до шести календарных месяцев перед месяцем исходного начала болезни.
- Отпускные: до шести месяцев перед месяцем **предпоследнего календарного рабочего дня до отпуска**. Пример 01.10.2026 → 29.09.2026 → март–август, не апрель–сентябрь.
- Дата согласованного позднего поступления отпускных не сдвигает расчётный период.
- Период может быть короче из-за известного начала службы; отсутствие PDF не считается коротким стажем.
- В знаменателе отпускных исключаются праздники и применимые отсутствия; в знаменателе больничного праздники сохраняются. При известном знаменателе из расчёта его можно ввести прямо.
- В заработок для среднего не включаются отпускные и пособия; начисления за работу вводятся отдельным полем.
- Если за весь период введён один и тот же подтверждённый заработок и нет исключённых дней, отпуск использует сохранение неизменного заработка. Вариант можно выбрать явно; один неизменный оклад не доказывает неизменность всех выплат.

Недостающие месяцы: известный оклад + средние доступные переменные составляющие того же периода. Нет образцов — оценка по окладу без неизвестных надбавок. В UI видны покрытие и допущения. Подтверждённый факт одного месяца заменяет его реконструкцию. Предположение о прежнем окладе явно названо.

### Пособия

| Основание | Срок | Формула |
| --- | --- | --- |
| Своя обычная болезнь | Дни 1–3 | Без обязательного пособия |
| То же | Дни 4–8 | Работодатель: 70% среднего дневного заработка |
| То же | С 9-го, стандартно до 182-го дня | Tervisekassa: 70% применимого дневного дохода |
| Hooldusleht 14 | С 1-го до 60-го дня | Tervisekassa: 80% |
| Hooldusleht 12 | С 1-го до 7-го дня | Tervisekassa: 80% |
| Hooldusleht 13 | С 1-го до 10-го дня | Tervisekassa: 80% |

Основания 14/12/13 выбираются по официальному листу; возрастные ограничения объясняются в редакторе. Исходный случай общий; месяцы/документы-продолжения не сбрасывают отсчёт. Отсутствие может длиться дольше оплачиваемого лимита.

Tervisekassa: соответствующий прошлогодний доход MTA /365. Год исходного случая сохраняется. В 2026 году у нового случая с 01.01.2026 применяется дневной максимум **126,87 € после процента**. Не распространять это число автоматически на 2027 и далее. Продолжение случая до 2026 не получает новый лимит автоматически.

**Разные типы вводимых ставок:** средний дневной доход до процента; готовое пособие за день после процента; общая подтверждённая сумма. Готовая ставка не умножается ещё раз на 70/80, общая сумма — на число дней.

Низкий/нулевой прошлогодний доход, родительский отпуск и особые причины требуют специальной базы. Нулевой доход не выдаётся за нулевое право на пособие: до ввода готовой ставки этот компонент неизвестен. Для особой причины обычные три дня ожидания и схема работодателя не применяются автоматически.

Открытый лист рассчитывается по текущую дату с указанием неизвестного конца; будущий остаток месяца не считается автоматически болезнью до последнего дня.

### Налоги и поступления

Обычные зарплатные взносы применяются к заработку и отпускным. Стандартное пособие работодателя исключено из töötuskindlustus/kogumispension, но участвует в его подоходной базе. Необлагаемый минимум работодателя используется один раз. Tervisekassa удерживает отдельно 22%, без повторного зарплатного необлагаемого минимума.

Основной экран — оценка **за период начисления**. Дата ожидаемого/фактического поступления хранится отдельно, фактическая сумма не меняется новым PDF. Если выплаты относятся к разным налоговым месяцам, точное кассовое распределение требует фактических начислений: текущий суммарный neto явно остаётся оценкой. Банковский учёт и автозапрос RTIP/MTA не добавлены.

## 5. Хранение и совместимость

IndexedDB `my-shifts`: **v4 → v5**. Старые stores сохраняются; добавлены:

- `events`, keyPath `id`: независимые ручные записи;
- `payroll`, keyPath `id`: месячные начисления/базы.

`settings.personalSettings` содержит личный owner, начало службы/учётного периода, его длительность/подтверждение конкретного периода (`confirmedPeriodStart`), способ обычной компенсации, историю ставок, годовые доходы и выбор личного плана для Google.

Событие: UUID, kind, owner, даты/время, статус, название/заметка/цвет, необязательные личные часы, compensation/baseAlreadyPaid, режим отсутствия, причина, caseStart/caseId, тип ставки/ставки/суммы, ожидаемая и фактическая выплата, связь с PDF, исключённые даты, timestamps. Точные enum/ограничения — в схеме. Android должен воспроизвести смысл, не названия IndexedDB.

Разделение на болезни/уход/отпуск выполнено полем kind с общими правилами формы. Продолжения объединяются caseStart/caseId, личные участки хранятся отдельными записями. Прерывание отпуска записывается как исключение дат, а не удаление исходного отпуска.

Backup **v2** содержит events/payroll и новые настройки. Чтение v1 поддержано. Запись/восстановление атомарные; перед заменой скачивается текущая копия. Проверяются существующие календарные даты, дубликаты ID, диапазоны и денежные значения. Неполный v2 не принимается «успешно» с потерей данных. OAuth-токены не включаются.

Удаление PDF не удаляет события/начисления. Возврат предыдущего PDF не откатывает ручные записи. Полный wipe удаляет всё локальное. При утрате источника связь требует проверки, а расчёт теряет точность.

## 6. Google Calendar и конфиденциальность

Локальное сохранение не выполняет сетевых записей. Новые OAuth scopes не запрашиваются.

Опция «Учитывать рабочие выходы и отсутствие» выключена по умолчанию. При включении явный существующий add/change/remove preview работает с личным рабочим планом. Причина болезни, сведения о ребёнке, заметки и деньги не экспортируются. Исходные ownership markers, проверка изменённых Google-событий и аккаунтная изоляция сохранены.

Связанный выход имеет один стабильный ключ; части после вычитания отсутствия получают отдельные стабильные ключи. Переход месяца не создаёт второе владение одной работой. Отсутствие PDF само по себе никогда не превращается в массовое удаление ранее экспортированных событий. Privacy/terms дополнены под новые данные и расчёты.

## 9. Проверки и выпуск

Автоматические проверки включают старые зарплатные примеры, новые формулы и пользовательские сценарии. Числа контрольных примеров:

- старая зарплата августа 2026: bruto **2736,19 €**, neto **2211,40 €** с исходными настройками;
- болезнь 10 дней с дневными базами по 100 €: **350 € работодателя +140 € Tervisekassa bruto**, Tervisekassa neto **109,20 €**;
- уход 10 дней с базой 100 €/день: **800 € bruto /624 € neto**;
- готовое пособие 80 €/день ×10 — **800 €**, не 640 €;
- отпуск 22–28.06.2026 со ставкой 100 € — **5 дней /500 €**, не семь дней;
- существующая полная смена и связанный ручной выход — одни часы, не два;
- отдельно проверяются повторный годовой/месячный отсчёт, предел после процента, введённый ноль, частичный месяц ставки, база уже оплачена, миграция v4 и копия v2.

Браузерные сценарии: импорт, навигация и рейтинг, offline, CSP, обновление SW; дополнительно личная запись без PDF с десятичной запятой, 320 px, сохранность редактора после «?», erakorraline с привязкой, уход и его сумма, долгое нажатие, атомарное прерывание отпуска.

Версия приложения повышается **0.2.1 →0.3.0** в package-файлах; версия базы **5**, backup **2**. `vite.config.ts` автоматически обновляет `version.json`/revision service worker. Адрес, scope и имя базы сохранены. Публикация — commit/push main → GitHub Actions → Pages; итоговый статус публикации фиксируется ниже после проверки.

### Известные практические границы

- Полный набор PDF не заменяет фактический заработок, сведения другого работодателя и табель.
- Особые основания, низкий доход и льготная ставка после родительского отпуска поддерживаются через подтверждённую ставку/сумму, не универсальную догадку.
- DST использует прежнюю модель планового местного времени; табельные фактически прошедшие часы требуют уточнения работодателем. Нельзя выдавать такую оценку за доказанный фактический табель.
- Точное кассовое распределение налогов при выплатах в разные месяцы не объявляется доказанным одним прогнозным neto.
- Официальный остаток ежегодного отпуска и подача документов в RTIP/медицинские сервисы не вычисляются/не выполняются.
- Проверка на физических Android/iPhone не заменяется запуском Chromium из Linux.

### Фактический итог выпуска

Локально: production build, 112 unit-тестов и 12 браузерных сценариев прошли. Публикация проверяется по GitHub Actions и публичному `version.json`; её фактический результат будет дописан после проверки.
