# PWA 0.4.0 — отмена и восстановление смен

Дата выпуска: 18.11.2026. Пользователь поручил реализацию с продуманным повторным импортом и публикацию по правилам проекта.

## Действия пользователя

Нажатие на день открывает отдельные действия для каждой рабочей записи: PDF-смены, дополнительного/экстренного выхода или koduvalve. Кнопка отмены показывает точную дату, код и время и объясняет влияние на часы, надбавки и Google. После сохранения день остаётся открытым. Другие записи того же дня сохраняются.

Отменённая смена теряет рабочий фон. На дне остаётся серая отметка `⊘`, в подробностях и списке — зачёркнутые код/время и восстановление. Смена с домашним дежурством после отмены только работы сохраняет синий домашний фон. Если отмена завершена или исходная смена изменилась, используется отметка `!` и пояснение. Легенда дополнена (18 обозначений). Записи можно отменять и восстанавливать offline.

Восстановление действует только на существующую исходную запись. Если смены уже нет, кнопка убирает только историческую отметку, не создавая старую смену поверх нового PDF. Если на время отменённой смены добавлена другая работа, восстановление сначала предлагает устранить пересечение; двойного начисления не возникает.

## Повторный импорт и история источника

Отмена — отдельная локальная запись, а не редактирование PDF. Сопоставление использует D-номер, источник, начало/окончание, тип и код, для ручной записи — также её постоянный ID. Имя файла и hash сами по себе не определяют идентичность смены. Техническая смена ordinal в sync key при добавлении другого кода не переносит отмену на чужую запись.

| Ситуация | Результат |
| --- | --- |
| Тот же PDF или те же параметры смены в новом файле | Отмена сохраняется. |
| Новый PDF с доступной строкой D-номера, смены больше нет | Отмена переходит в `removed`. Смена отсутствует по самому PDF. |
| Время, длительность, код или тип изменились | Старое решение не применяется к новой смене; статус `changed` либо `removed` в зависимости от наличия соответствующей рабочей записи. Новая смена действует по PDF. |
| После исчезновения/изменения старая смена появилась вновь | Смена действует; прежняя отмена остаётся завершённой. Показано предупреждение, можно отменить заново. |
| Возвращена предыдущая версия PDF | Выполняется та же сверка. Завершённая отмена не оживает. |
| Сам PDF или строка D-номера недоступны | Это не доказательство исчезновения смены. Отмена сохраняется до появления источника. |
| Удалён соседний PDF для ранее объединённых 16+8 | При отсутствии доказательства изменения отмена подавляет оставшуюся известную 16-часовую часть. Появление новой доступной строки без продолжения — изменение, требующее нового решения. |
| Изменена/удалена ручная исходная запись | Отмена завершается или требует нового решения; повторное появление не активирует старую отмену. |
| Несколько совершенно одинаковых исходных записей | Отменяется выбранный экземпляр; количество дублей входит в снимок. Изменение количества требует нового решения. |
| Переключён D-номер | Отмена не переносится на другого сотрудника. |

В предпросмотре импорта показаны итоги для отмен, включая изменения на границе месяца. Google ещё не меняется. После подтверждения PDF и переходы состояний отмен сохраняются в одной IndexedDB-транзакции. То же правило применяется при возврате revision и восстановлении резервной копии. Терминальные состояния `removed`/`changed` не активируются автоматически; небольшая история видна до явного скрытия пользователем.

## Расчёты и Google

`personalPlan()` хранит исходный PDF для сравнения, доступные исходные интервалы после отмен, отдельно отменённые интервалы, пропущенное по отсутствиям время и действующий план. Отмены применяются перед расчётом отсутствий и пересечений. Связанный вручную выход отменяется вместе с тем же PDF-интервалом один раз, в том числе при недоступном источнике. Если новый доступный PDF удалил или изменил связанный выход, ручная запись с устаревшей связью остаётся для проверки и не превращается автоматически в независимую дополнительную смену. Пользователь может открыть её и явно исправить связь. Независимые заметки и koduvalve сохраняются.

Рабочий план используется карточкой текущей/следующей смены, календарём, анализом, своей строкой рейтинга нагрузки, прогнозом выплат и учётным периодом. В анализе отдельно указаны отменённые рабочие/домашние часы; сравнение с исходным PDF остаётся подписанным сравнением. Отмена не является неоплачиваемым отсутствием и сама по себе не уменьшает оклад или норму. Ночные/праздничные/домашние надбавки и оплата Erakorraline пересчитываются по оставшемуся времени. Подтверждённые пользователем фактические начисления не переписываются.

Отмены работают в обычном Google diff независимо от настройки учёта отсутствий. Синхронизация предлагает remove, восстановление — add; отмена и восстановление до отправки дают прежний план без дублей. При недоступном PDF отмена также подавляет сохранённые draft этого интервала и части, ранее разбитые отсутствием. Ownership markers, аккаунты, напоминания, журналирование и обработка удалённых Google ID остаются общими для синхронизации. Реальной автоматической отправки при сохранении нет.

## Данные и перенос в APK

Версия **0.3.6 → 0.4.0**. IndexedDB **v5**, новых stores нет. В `events` добавлен `kind: cancel` с обязательными owner и снимком `cancellation.target`: source (`pdf`/`manual`), key, eventId для manual, start/end (минуты условного UTC для таллинского wall time), kind (`hours`/`home`), raw, occurrence/copies для дублей, boundary16 для исходной части на границе месяца. `cancellation.state`: active/removed/changed. Даты и диапазоны проверяются Zod. Новые записи создаются по явному действию пользователя; старые не требуют миграции.

Резервная копия **v3** сохраняет отмены и их состояния; v1/v2 продолжают приниматься. В v2/v3 обязательны массивы events/payroll. Старые приложения не должны принимать v3: перед восстановлением нужно обновить приложение. После restore проверяется согласованность с восстановленным набором PDF; завершённые решения не реактивируются.

Для APK перенести модель снимка/состояний, атомарную сверку с источником, интерфейс отмены и восстановления, предупреждения импорта, все потребители действующего плана, формат backup v3 и перечисленные пограничные случаи. Основные файлы: `shift-cancellations.ts`, `cancellation-view.ts`, `personal-types.ts`, `personal.ts`, `personal-view.ts`, `db.ts`, `main.ts`, `employee-workload.ts`, `analysis-view.ts`, `backup.ts`.

## Проверки и публикация

Локально прошли **139 unit/regression-тестов** (один тест с необязательным внешним PDF пропущен) и полный набор из **24 браузерных сценариев**. Проверены выборочная отмена и восстановление, независимость koduvalve, часы/надбавки/своя нагрузка, Google add/remove diff и подавление сохранённых частей при отсутствии источника, связь с PDF, дубли, переходы месяцев и недоступный соседний PDF, атомарное завершение отмены при импорте, возврат revision, повторное появление, backup v3 и offline. Новый браузерный сценарий запрещает восстановление поверх дополнительной работы.

В production-сборке с `/duty/` отдельно пройдён сценарий отмена → неизменённая смена → исчезновение → повторное появление → новая отмена → восстановление → offline. История содержит 11 версий с раскрытой 0.4.0, легенда — 18 обозначений. На 320 px проверены обе темы и отсутствие горизонтального переполнения; выполнен визуальный просмотр панели отменённой смены. `git diff --check` и сборка с `/duty/` прошли. Снимки и PDF только синтетические, в репозиторий не добавлены. Реальный Google-аккаунт и физические устройства не использовались.

Результаты публикации будут записаны после завершения workflow и проверки публичной версии.
