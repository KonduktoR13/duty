# PWA 0.3.4 — история обновлений в настройках

Дата: 13.11.2026. Только PWA; APK не изменялся. Реализовано локально, результат публикации фиксируется ниже после проверки. Дополнение к [0.3.3](pwa-0.3.3-android-handoff.md).

## Что изменилось

В настройках перед текущей версией добавлена строка **«История обновлений»**, подпись «Версии, даты и изменения». Нажатие открывает отдельный экран внутри существующего диалога.

- Восемь версий от 0.1.0 до 0.3.4, новые сверху. Для каждой — номер, дата и короткое название; при раскрытии — понятный пользователю список изменений.
- Текущая версия помечена «Текущая» и раскрыта сразу. Остальные свёрнуты. Можно раскрыть несколько версий одновременно, в том числе клавиатурой.
- Версии 0.2.0–0.3.3 описаны по документам `docs/*-android-handoff.md` и релизным коммитам; даты 0.2.0/0.2.1 — 13.10.2026, 0.3.0/0.3.1/0.3.2 — 30.10.2026, 0.3.3/0.3.4 — 13.11.2026.
- Ранние изменения выходили с одним номером **0.1.0**. Поэтому у этой версии показан период **«Август — сентябрь 2026»**, пояснение об общем номере и отдельные даты изменений по Git: 22/23/25/31 августа, 1/5 сентября. Эти даты не выдаются за восстановленные даты отдельных нумерованных релизов.
- Кнопка «Назад к настройкам» возвращает прежнюю прокрутку и фокус на строку истории. Кнопка «Закрыть» закреплена снизу; Escape закрывает диалог обычным способом. Заголовок остаётся доступен при прокрутке.
- Используются цвета текущей темы. Длинные названия переносятся, список работает на 320 px без горизонтального переполнения.
- История встроена в сборку и доступна без интернета. GitHub API, внешние документы и персональные данные при просмотре не запрашиваются.

## Данные и сопровождение

`src/update-history.ts` содержит массив `updateHistory` и функцию представления `updateHistoryView()`.

Запись версии: `version`, ISO `date`, `title`, массив `changes`; у ранней 0.1.0 дополнительно `earlier` с датированными группами. Для даты используется русский формат с явным UTC. Текущая версия определяется по `__APP_VERSION__`, как в настройках. Состояние раскрытия временное, при повторном открытии снова раскрывается текущая версия.

**При каждом следующем выпуске:** повысить версию пакета, добавить запись в начало `updateHistory`, указать дату выпуска и краткие изменения для пользователя. Технические подробности и перенос в APK продолжать документировать отдельно в `docs`; не выводить пользователю историю CI, внутренние имена функций и рабочие обсуждения.

Источники для восстановления истории: release commits `6d5a134` (0.2.0), `b93c283` (0.2.1), `f6c1cbf` (0.3.0), `1739002` (0.3.1), `69b7420` (0.3.2), `4fe4a0e` / `c106991` (0.3.3); ранние коммиты от `c612da3` до `3504b8e`. Даты ранних изменений взяты из истории Git, отменённое разбиение Google-смен на части не включено как действующая возможность.

## Перенос в APK

Воспроизвести пункт настроек, список версий, даты, тексты, раскрытие текущей версии, возврат/закрытие и работу offline. Привязать метку «Текущая» к фактической версии APK: не объявлять PWA-функции реализованными в APK до переноса. Историю платформ вести с учётом фактических выпусков каждой платформы.

Файлы PWA: `update-history.ts` (тексты и представление), `settings-view.ts` (вход), `main.ts` (открытие/возврат/фокус), `settings.css` (оформление), `e2e/app.spec.ts` (проверка навигации, клавиатуры, offline и обеих тем).

Версия приложения **0.3.3 → 0.3.4**. IndexedDB **v5**, backup **v2**, миграции не требуются. Графики, личные записи, расчёты выплат и Google-синхронизация не изменены.

## Проверки

**122 unit/regression-теста и 18 браузерных сценариев прошли**, включая новый сценарий истории: открытие, текущая версия, ранние даты, раскрытие с клавиатуры, возврат/фокус, обе темы на 320 px и холодный запуск offline. Production-сборка и `git diff --check` прошли. Результат публикации дополняется после проверки.
