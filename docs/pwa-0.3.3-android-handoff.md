# PWA 0.3.3 — отпуск P-et, ручное koduvalve и редактирование

Дата: 13.11.2026. Только PWA; APK не изменялся. **Опубликовано на GitHub Pages; публичная версия 0.3.3 проверена.** Дополнение к [базовой модели ручных событий и выплат 0.3.0](pwa-0.3.0-android-handoff.md) и [предыдущему выпуску 0.3.2](pwa-0.3.2-android-handoff.md). Этот документ — лог изменений и спецификация для последующего переноса в APK.

## 1. P-et — дополнительный отпуск

В предоставленном декабрьском PDF у D12 22–30 декабря стоит P, 31 декабря — P-et. Ранее последний день был неизвестным `other`, серой ячейкой и не попадал в отпускные. Теперь:

- `LeaveCode = 'P' | 'P-et' | 'LHPu'`. Код P-et сохраняется дословно, не сливается с P и не превращается в часы.
- Парсер распознаёт P-et без учёта регистра, включая повёрнутые координатные таблицы; каноническое значение `P-et`.
- Вид дня `leave-vacation`, отпускной цвет, значок солнца в карточке, описание **«Дополнительный отпуск · eriteenistuja lisapuhkus»**. Легенда включает P / P-et. LHPu сохраняет прежнее значение отпуска по уходу за ребёнком.
- P-et учитывается в числе дней отсутствия, оплачиваемых отпускных днях и уменьшении нормы/оклада по тому же существующему оценочному пути, что P. В прогнозе по PDF используется сохранённая дневная ставка отпускных. Государственные праздники исключаются существующим правилом отпускных; отдельный новый механизм начисления стажевых дней не вводился.
- В личном прогнозе даты P-et, уже покрытые ручным отпуском/обработанным отсутствием, не оплачиваются повторно. Ручной период с подтверждённой ставкой позволяет уточнить оценку.
- Неизвестные коды Õ/TK4 и прочие сохраняются как `other`.

Название уточнено по документам Päästeamet: **eriteenistuja lisapuhkus**, дополнительный оплачиваемый отпуск. В [sisekorraeeskiri 21.03.2024 № 1.1-3.1/74](https://adr-docs.karlerss.com/uf07TWqbApnfzPaWilsvpvOfVwfyDiFG/P%C3%A4%C3%A4steameti%20sisekorraeeskiri.pdf), раздел 6, используется это название и описан отпуск за стаж. Аналогичное название есть в [официальном документе Päästeamet](https://adr.rescue.ee/paa/fail/1169171/subfile/1). Общая правовая основа — [PäästeTS §22](https://www.riigiteataja.ee/akt/130062026024). Сам PDF не содержит расшифровки P-et: соответствие кода этому виду отпуска установлено по контексту пользователя и последовательности P → P-et. Не выдавать эту расшифровку за легенду, напечатанную в PDF.

### Уже сохранённые данные

Повторный импорт не нужен. `migrateMark()` преобразует `other/P-et` в `leave/P-et`. `candidatesForMonth()` пересобирает leaveDates/leaveCodes по актуальным marks для каждого D-номера. При загрузке `refresh()` записывает изменённые candidates и синхронизирует верхние marks/leaveDates/leaveCodes выбранной исходной строки. Исходные PDF, часы и остальные строки сохраняются. Старые записи без candidates используют существующую миграцию из PDF либо legacy marks. При откате старой ревизии преобразование применяется снова.

**Для APK:** добавить P-et не только в UI, но и в парсер, доменную модель, все расчёты отпуска, чтение уже сохранённых отметок и проверку резервных копий.

## 2. Ручное домашнее дежурство

Новый вид личного события **`kind: 'home'`**, подпись **«Koduvalve · дома»**, в той же форме «Добавить». Основной календарь не получает отдельную постоянную форму.

- Даты начала/окончания, время с минутной точностью, статус и заметка. Длительность произвольная; существующие общие кнопки длительности 4/8/12/24 ч остаются. **Специального шаблона на 2 ч нет** — пользователь отдельно отказался от него.
- «Начать после смены этого дня» показывается, когда на дату есть рабочий интервал. Используется личный план, включая внесённую работу и отсутствия. Действие переносит интервал к окончанию смены и **сохраняет введённую длительность**, не навязывает 2 или 4 часа. Корректно меняет дату при переходе через полночь. После переноса время можно изменить вручную.
- Пример: смена 14 декабря 08:00 → 15 декабря 06:00 (22 ч). Можно добавить home 15 декабря 06:00–08:00 либо любой другой фактический интервал. Эти даты не подставляются пользователю автоматически при обновлении.
- Требуются начало и конец, конец позже начала, максимум 48 ч на запись, как для остальных ручных интервалов. Событие привязано к личному D-номеру.
- На дне маркер V; в карточке и списке — обычная редактируемая строка.

### Расчёт и пересечения

`isWork()` в модели означает событие с интервалом, участвующее в построении плана; туда включён home. При этом `PersonalInterval.kind = 'home'`, `source = 'home'`, raw `V<длительность>`, стабильный ключ `manual:<id>`. Это **не onsite-работа**.

- Домашние часы попадают в `stat.home` и `homeDutyHours`, **не** в рабочие/дополнительные/Erakorraline, ночные, праздничные или сверхурочные часы. Учётный баланс использует только work.
- Надбавка использует существующую настройку `homeDutyPercent` (по умолчанию 12%): `roundMoney(baseSalary / normHours × percent / 100) × hours`, затем округление итоговой суммы до центов. При смене оклада внутри месяца расчёт делится по датам применимости; строка подробностей использует те же ставки. На границе месяца минуты делятся по полуночи.
- Надбавка входит в bruto работодателя и обычную зарплатную налоговую базу. Если фактический заработок месяца уже введён в начислениях, действует прежний приоритет факта над прогнозом — ручные часы не прибавляют деньги к факту повторно.
- Предпросмотр формы показывает изменение bruto. Анализ показывает домашние часы отдельной строкой при их наличии; подробности выплаты — в «Как посчитано».
- Правила оплаты сверены с [Päästeameti palgajuhend, 01.01.2026, раздел 4.5](https://www.rescue.ee/files/2026-01/paasteameti-palgajuhend.docx). Новая функция повторно использует существующий расчёт V, не вводит отдельный тариф для ручной записи.
- Пересечение с работой, другим домашним интервалом или отсутствием требует исправления. Полностью совпадающее домашнее дежурство из PDF можно явно связать: считать время один раз. Типы также должны совпадать: onsite-работу нельзя заменить home через галочку связи.
- При последующем изменении PDF сохраняется существующая проверка связи/конфликтов. PDF не содержит точного времени V: его интервалы строятся по прежним допущениям `workIntervals`. Автоматическое отождествление разных временных интервалов или одного числа часов не выполняется.
- При включённой пользователем синхронизации личного плана Google получает timed-событие типа home с подписью Koduvalve. По умолчанию личная синхронизация выключена; действующие ownership/account guards сохраняются.

## 3. Редактирование без лишних кнопок

Редактор существовал и раньше: нажатие на личную запись в карточке дня или списке открывает её для изменения. Теперь справа вместо стрелки стоит карандаш, доступное имя кнопки — «Изменить: …»; home использует этот же путь.

Можно менять даты, время, статус, заметку и прочие поля своего типа. Сохранение обновляет запись по прежнему id; перезагрузка сохраняет изменения. Внизу редактора есть «Удалить запись» с существующим подтверждением. Закрытие несохранённых изменений, ошибки записи и сохранение формы при открытии справки используют прежние механизмы. Отдельные постоянные кнопки редактирования/удаления в ячейках календаря не добавлены.

## 4. Хранение и файлы

Версия приложения **0.3.2 → 0.3.3**, IndexedDB **v5**, JSON backup **v2**. Новые stores не нужны. Расширены enum событий и enum отпусков во всех уровнях backup: marks, leaveCodes, candidates, месяцы и ревизии. Старые резервные копии читаются, новые сохраняют home и P-et. Приложения старых версий могут отвергнуть эти новые значения; перед переносом в APK расширить его валидатор.

Основные файлы:

- `types.ts`, `parser.ts`, `roster.ts`, `main.ts`: код отпуска, парсинг, преобразование сохранённых данных.
- `calendar-view.ts`, `month-analysis.ts`: отпускной вид и дни для расчёта.
- `personal-types.ts`, `personal.ts`: home, интервалы, конфликты, выплаты и экспорт Google.
- `personal-editor.ts`, `personal-view.ts`, `personal.css`: общая форма, перенос после смены, маркер V, карандаш, часы анализа, узкая форма.
- `backup.ts`: чтение/восстановление новых значений; тесты в `tests` и `e2e/personal.spec.ts`.
