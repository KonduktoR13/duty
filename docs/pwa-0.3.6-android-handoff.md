# PWA 0.3.6 — полная легенда календаря

Дата выпуска: 18.11.2026. Пользователь поручил дополнить легенду и продолжить публикацию по правилам проекта.

## Поведение

В 0.3.5 ручные записи получили фон дня, но легенда содержала только семь прежних пояснений PDF. Теперь `src/calendar-legend.ts` описывает две группы: «Смены и отметки» и «Ручные записи», всего 17 обозначений. Счётчик вычисляется из списка.

Все восемь ручных типов перечислены явно: дополнительный выход, Erakorraline, koduvalve, отпуск, больничный, уход за ребёнком, компенсационный отдых, своя запись. Для рабочих выходов показаны цвета суточной и прочих смен. Для заметки показана палитра из шести цветов. Пояснение уточняет стандартный фиолетовый цвет отсутствий и сохранение рабочего фона при заметке на день смены.

В основной группе отпуск P/P-et и отпуск по уходу LHPu разделены; ручной больничный по уходу не смешивается с LHPu. Есть образцы смешанного фона работы и koduvalve. Образцы используют те же CSS-классы, что сами дни, включая личный цвет и текущую тему.

У раскрытого блока снято ограничение 240 px, обрезавшее бы длинную легенду. Строки переносятся, образцы не сжимаются. Блок остаётся сворачиваемым, доступен без сети и на экране 320 px.

## Данные и перенос в APK

Версия **0.3.5 → 0.3.6**, IndexedDB **v5**, backup **v2**. Миграции не нужны. Правила окраски дней, расчётов и синхронизации не меняются. В APK перенести обе группы, полный список типов, пояснения длительности/цвета записи и раскрытие без обрезания. История приложения дополнена записью 0.3.6.

## Проверки и публикация

Локально прошли **125 unit/regression-тестов** (один тест с необязательным внешним PDF пропущен) и **20 браузерных сценариев**. Новый сценарий проверяет все восемь ручных типов, шесть цветов заметки, совпадение цвета образца с цветом дня, отсутствие обрезания и горизонтального переполнения на 320 px в обеих темах, сворачивание и доступность offline. История проверяет текущую 0.3.6 и десять версий. Сборка с `/duty/` и `git diff --check` прошли.

Публикация и проверка публичной версии будут зафиксированы после завершения workflow.
